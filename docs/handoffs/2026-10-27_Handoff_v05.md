## Current state

- Learned from this PR's first CI run, and fixed in it:
  - pak ran `apt-get update` and `apt-get install` in the container for
    every system requirement it lists, including ones the image has and
    build-only ones (`cmake`, `libabsl-dev`). `PKG_SYSREQS: false` stops
    it; a dependency needing a library the image lacks now fails the job
    (ADR 0022).
  - pak kept Matrix at the version R ships with (1.7-5) while CRAN had
    1.7-6, on Windows as well as in the container. `upgrade: 'TRUE'`
    fixes it in the container (Matrix is compiled from source, about 2.5
    minutes). On Windows it made pak fail to download the recommended
    packages from P3M, so it is off there and Windows checks against R's
    own Matrix.
  - The "hard" job restored the "all" job's package cache through the
    shared restore key, so prioritizr was installed and its tests ran
    (`SKIP 0`). This probably affected the old Ubuntu "hard" job too.
    `cache-version` is now the dependency set.
  - With a clean library, the Windows "hard" job failed: nine tests in
    `test-wtw.R` read files with `sf::read_sf()`, which needs tibble (not
    a dependency). They now use a `read_vector()` test helper
    (`sf::st_read()`, a data frame).
