# Session Handoff: 2026-10-29

## Summary

One-issue session: #108, ninth issue in the v0.2.0 milestone.
`write_raster_file()` is exported (one raster to one named file), and with
`datatype = NULL` a raster with no stored data type is no longer an error:
its type is inferred from the values, with a message (ADR 0027). Version
0.1.0.9008.

## Completed

- This PR (Closes #108): `write_raster_file()` exported (`@family raster`,
  in `_pkgdown.yml` through `has_concept("raster")`); one internal writer
  (`write_raster()`) decides every file's data type; `write_rasters()`
  passes `datatype` through (its `layer_datatypes()` and
  `multiband_datatype()` are gone); `align_raster()` drops
  `input_datatype()`'s error; `extract_layers()` no longer stops on a layer
  with no type and uses the shared `terra_datatypes()` list. ADR 0027
  (amends ADR 0010 and ADR 0014), inventory, `NEWS.md`, tests and snapshots.

## Current state

- Gotcha: `align_raster()` passes `stored = FALSE` to the internal writer
  for an in-memory input, because terra may put the warped result in a
  temporary file whose stored type is terra's default (`FLT4S`), not the
  data's; the inference then reads the values. A test covers it with
  `terraOptions(todisk = TRUE)`.
- The inference message says "the raster" rather than "`x`", since it also
  appears from `extract_layers()` and `align_raster()`.
- Tests that need stable messages or error paths `setwd()` to a temporary
  folder and use relative paths, as `test-extract.R` does.
- No follow-up issues opened.
