## Current state

- Narrower choices made while building, recorded in ADR 0010: a
  `SpatRaster` read from a file counts as a file input; `datatype = NULL`
  uses the input file's type and an in-memory input needs `datatype` to be
  written; values written as integers are rounded (terra truncates
  otherwise); an input whose extent misses the template is an error.
- Equivalence: the fixture outputs of `gdalwarp` (`align_pu()`) are stored
  in the test. A one-off local check on the mb_prairie `pu_1km.tif` against
  NAT_DATA_20261009 `_1km/idx.tif` gave the same 70,630 cells and values as
  the `pu_1km_align.tif` `align_pu()` wrote (in about 4 seconds).
- Gotcha: a GeoTIFF read back stores the CRS in its own WKT form, so tests
  compare a written result's CRS with `terra::same.crs()`; only in-memory
  results carry the template's CRS text exactly.
- `align_raster` is the first example alphabetically, so R CMD check reports
  its elapsed time (about 6 s) including loading terra and sf; the function
  itself takes well under a second there.
