## Summary

One-issue session: #67, `NCCID` as an integer.

## Completed

- #67 (this PR): raster values keep their stored type (ADR 0019).
  `rasterize_aoi()` returns integer cell numbers and keeps an integer
  template's type; `polygonize_raster()` returns an integer `value` column
  when the raster stores integers (`terra::is.int()`). So `NCCID` is an
  integer in `create_1km_grid()` and in `pu_1km.shp` (`N(9,0)`). Tests on
  INT4S and FLT4S fixture templates, including the `.dbf` field types read
  back; `NEWS.md`, version 0.0.0.9013, notes in ADRs 0008, 0017, 0018 and
  the inventory.

## Current state

- One-off local check on NAT_DATA_20261009 and the mb_prairie AOI:
  `pu_1km.shp`'s `.dbf` now matches wtw-data-prep2's (fields `NCCID` and
  `PUID` both `N(9,0)`, identical values, same file size).
- Learned: with terra 1.9.34, `terra::as.polygons()` always returns doubles,
  `terra::extend()` drops a raster's integer flag (so `rasterize_aoi()`
  sets it again with `terra::as.int()` for `crop = FALSE`), and
  `terra::writeRaster()` without a `datatype` writes an integer raster as
  `INT4U`. constechr's writers always pass a data type.
