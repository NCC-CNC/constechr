## Current state

- Same result as the original (stored values, terra 1.9.34) and as
  `prioritizr::boundary_matrix()` on the cells as polygons to 1e-6 m. A
  hand-worked known answer at the equator (WGS84 formulas) holds to 1e-9.
- Changes from the original: takes a path as well as a `SpatRaster`; cli
  errors (no CRS, projected, not a raster); an empty raster gives a matrix
  of zeros. The matrix is built in one `sparseMatrix(symmetric = TRUE)`
  call instead of `forceSymmetric()` and a diagonal assignment.
- Gotcha: on a raster spanning 360 degrees, `terra::adjacent()` wraps, so
  the first and last cells of a row are neighbours; prioritizr on polygons
  does not join them. Kept as the original does, documented and tested.
- Markdown not linted locally (no Node.js on this machine); checked by eye.
